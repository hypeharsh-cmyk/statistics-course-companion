# Statistics — Textbook + Mock Tests

Two self-contained HTML pages sharing one design system:

- **/** — the textbook. 5 chapters, 20 interactive canvas figures, Z/t tables, formula sheet.
- **/mock-tests.html** — three full-length mock papers (50 marks, 2.5 h each) with complete worked
  solutions, a countdown timer, per-candidate saved answers and self-scoring.

No framework, no bundler, no build tooling beyond one concatenation script.

## Layout

```
book-src/          the book, in editable parts — THIS is what you edit
  00-head.html     <head>, all CSS, MathJax config
  ch1..ch5.html    one chapter each
  99-tail.html     appendices + every figure's drawing code
mock-src/          the mock papers, same pattern
  00-head.html     mock-only CSS + the @@BOOK_STYLE@@ token
  paper1..3.html   one paper each: 8 questions + solutions
  99-tail.html     tables, results, and the test-app logic
static/            files copied verbatim into the deploy folder
  _headers         security + cache headers (Cloudflare applies these)
  404.html         not-found page
  favicon.svg
  robots.txt
public/            BUILD OUTPUT — deleted and regenerated by the build, never edit
statistics-book.html   standalone single-file copy, for offline reading / emailing
build.mjs          concatenates book-src/ into public/index.html
```

## Commands

```bash
npm run build     # book-src/ -> public/
npm run dev       # build, then serve public/ at http://localhost:4173
npm run sync      # build, and refresh the root statistics-book.html copy
npm run deploy    # build, then upload public/ to Cloudflare Pages
```

Edit a chapter in `book-src/`, run `npm run build`, and `public/index.html` is the new book.
The build warns if `statistics-book.html` has fallen out of step; `npm run sync` refreshes it.

## Deploying to Cloudflare

### Option A — direct upload (recommended, no repo wiring)

```bash
npm run deploy
```

That runs `wrangler pages deploy public`. The first run asks you to log in and to name the
project (`statistics-book` is a good choice); after that the same command redeploys. You get a
`*.pages.dev` URL immediately.

### Option B — connect the Git repo

This folder lives inside the larger `website-building` repo, so in the Cloudflare Pages
**Create project → Connect to Git** flow set:

| Setting | Value |
| --- | --- |
| Root directory | `stats` |
| Framework preset | None |
| Build command | `npm run build` |
| Build output directory | `public` |

Cloudflare then rebuilds on every push. `public/` is gitignored on purpose — Cloudflare
generates it during the build.

### Custom domain

Pages project → **Custom domains** → add the hostname. If the domain is already on Cloudflare
DNS the record is created for you; TLS is automatic.

## Headers

`static/_headers` sets `nosniff`, `Referrer-Policy`, `X-Frame-Options`, a `Permissions-Policy`
and a Content-Security-Policy. The CSP allows exactly what the book uses:

- `script-src` — inline scripts (the whole book is inline) plus `cdnjs.cloudflare.com` for MathJax
- `style-src` — inline styles
- `font-src` — `cdnjs.cloudflare.com`, where MathJax fetches its math fonts
- everything else falls back to `'self'`, with `object-src 'none'`

**If you ever add an external image, font, script or API call, add its origin here or it will
be silently blocked in production.** `_headers` is applied by Cloudflare, not by any local dev
server, so a broken CSP will not show up in `npm run dev` — test it with the CSP check below.

## Verifying before deploy

`npm run dev` serves the built folder but, like every plain static server, ignores `_headers`.
To test the real production headers, serve `public/` through something that applies them
(Cloudflare's own `wrangler pages dev public` does), then confirm in the browser console that
there are no `Content-Security-Policy` violations and that the math has rendered.

The page is fully self-contained apart from MathJax. If you ever want zero third-party
requests, download the MathJax `es5/` bundle into `static/mathjax/`, point the `<script src>`
in `book-src/00-head.html` at it, and drop `cdnjs.cloudflare.com` from the CSP.

## Running the mock tests with several candidates

The mock page is static — there is no server and no account. Each browser stores its own data:

- On first open it asks **who is sitting the paper**. Up to five names per device.
- Answers, timer, marks and peeked-question flags are saved per name, in that browser's
  `localStorage`. Switching names switches all of it.
- **Results** shows the signed-in candidate's three papers, plus a comparison table of every
  candidate saved on that device.

So if all four or five people open the Cloudflare URL **on their own phones or laptops**, each
device keeps its own single candidate and nobody can see anyone else's marks. The name picker
matters when people share one machine. To compare scores across devices, use **Print** to save a
finished paper (answers and solutions included) as a PDF and send it on.

If you later want one shared leaderboard across devices, that needs a backend — Cloudflare Pages
Functions with a KV namespace is the smallest version. Ask and it can be added; the current page
is deliberately backend-free so it costs nothing and cannot leak.

## Where the mock questions come from

Papers 1 and 2 mirror the May 2026 end-term (`IIFT_Introductory_Statistics_MST02_Question_Paper.md`)
question for question: same eight topics, same 5+5+6+6+7+6+7+8 mark split, same two-and-a-half
hours. Paper 3 keeps that skeleton but adds a second step to every question — a conditional
probability, a required sample size, a Type II error, a p-value bracketed between two table
columns, tied ranks.

Every numerical answer was computed and cross-checked against the χ², t and Z tables shipped on
the Tables tab, so the values a student reads off the table match the printed solution.

One deliberate exception: Paper 3 Question 3(c) uses the finite population correction, which is
not in the course notes. The formula is given inside the question, so it tests reading and
applying rather than recall.
